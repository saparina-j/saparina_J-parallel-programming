# Лабораторная работа №4: Умножение квадратных матриц на GPU (CUDA)

## Цель работы
Модифицировать последовательную программу умножения квадратных матриц (из лабораторной работы №1) для параллельного выполнения на графическом процессоре с использованием технологии **NVIDIA CUDA**. Провести серию вычислительных экспериментов для оценки производительности при различных размерах матриц и конфигурациях сетки блоков (`blockDim` и `gridDim`).

---

## Оборудование и среда тестирования
* **Графический процессор (GPU):** NVIDIA Tesla T4 (архитектура Turing, `sm_75`, 16 ГБ видеопамяти)
* **Компилятор:** NVIDIA CUDA Compiler (`nvcc` v13.0) с флагом оптимизации `-O3`
* **Среда выполнения:** Google Colab (Ubuntu Linux)

---

## Структура папки `lab4/`
* `matrix_cuda.cu` — исходный код программы на C++/CUDA с реализацией ядра умножения матриц на GPU, контрольной функцией на CPU и замером времени через `cudaEvent_t`.
* `run.sh` — bash-скрипт для автоматической компиляции и запуска всех экспериментов.
* `results.csv` — таблица с сырыми результатами всех проведенных замеров.
* `plot_results.py` — скрипт на Python (`matplotlib`) для генерации графиков производительности.
* `README.md` — текущий отчет с описанием алгоритма, результатами и выводами.

---

## Инструкция по сборке и запуску

```bash
# Компиляция программы
nvcc -O3 -arch=sm_75 matrix_cuda.cu -o matrix_cuda

# Запуск с параметрами: ./matrix_cuda <размер_матрицы_N> <размер_блока_BLOCK_SIZE>
./matrix_cuda 1024 32
```

Или запуск всей серии экспериментов одним скриптом:
```bash
chmod +x run.sh
./run.sh
```

## Выводы

1. **Эффективность GPU-ускорения.** Использование графического ускорителя NVIDIA Tesla T4 позволило сократить время перемножения матриц размером $1024 	imes 1024$ с **3.34 секунд** на CPU до **5.36 миллисекунд** на GPU, обеспечив прирост производительности в **623.5 раза**.
2. **Влияние размерности задачи.** На малых матрицах ($256 	imes 256$) вычислительной нагрузки недостаточно для полной утилизации всех потоковых мультипроцессоров (SM) видеокарты. С ростом размера матрицы до $1024 	imes 1024$ и выше степень параллелизма растет, что приводит к резкому увеличению коэффициента ускорения.
3. **Влияние конфигурации сетки и блоков.**
   * Конфигурация `8×8` (64 потока на блок) показывает худшее время во всех тестах из-за недостаточной загрузки мультипроцессоров и низкой эффективности сокрытия задержек при обращении к глобальной памяти.
   * Оптимальной конфигурацией является блок `32×32` (1024 потока — аппаратный максимум для блока в CUDA). На матрице $2048 	imes 2048$ переход с сетки блоков `16×16` на `32×32` дополнительно сократил время вычислений на **41.5%** (с 56.82 мс до 33.23 мс).
